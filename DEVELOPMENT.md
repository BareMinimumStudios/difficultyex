## Build

Use Java 21 and the checked-in Gradle wrapper. The project uses Cloche for shared Fabric and NeoForge sources. Dependency versions are pinned in [libraries.toml](libraries.toml).

```powershell
.\gradlew.bat clean test build
```

On Linux or macOS, use `./gradlew clean test build`. Loader-specific distributable JARs are written to `build/libs`. The build includes the studio license and inherited MIT notice in each JAR.

## IntelliJ IDEA

Import `build.gradle.kts` as a Gradle project and select Java 21 for the project and Gradle JVM. Run `clean test build` through the Gradle tool window. Loader client/server configurations are generated by the build. Dependency sources can be generated through `genDependencySources`.

The common variants include a server capability alias needed by Cloche 0.19.13's IDEA import. Mixins and client Java live in `src/loaderShared/java`, compiled by both loader source sets against full game classes so IDEA can inspect actual injection instructions. Shared gameplay code retains the common API. See [IDE validation](docs/IDE_RELEASE_PREP_2026-10-29.md). Compilation alone does not validate injection behavior.

## Publishing

The [manual publish workflow](.github/workflows/publish.yml) is gated to `1.21.1` and builds both loaders before uploading. Review version, changelog, remaining acceptance and credentials before dispatch. See [release steps and preflight](docs/RELEASING.md). The release helper has ten additional Python regression tests.

[CurseForge copy](docs/CURSEFORGE.md), [Modrinth copy](docs/MODRINTH.md), [short summaries](docs/SUMMARIES.md) and [brand assets](docs/BRANDING.md) are maintained separately. Their branch URLs resolve after these files are pushed. No upload or publication is implied by editing them.
