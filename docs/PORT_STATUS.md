# DifficultyEx 1.21.1 Port Status

Development snapshot: October 9, 2026. Not release-ready.

## Working foundation

- Builds on Gradle 9.8.0, Cloche 0.19.13, Java 21, and Kotlin.
- Fabric and NeoForge project layouts; Fzzy Config, no owo-lib/KSP.
- Fzzy fields now use validated wrappers so all configured progression, mob, world, structure, and nameplate fields are eligible for in-game edit controls (rather than raw values that never render editable controls). Nameplates use both `@property:NonSync` for Fzzy Kotlin reflection and `@field:NonSync` for JVM metadata, regression-tested against both loader bytecodes. The earlier field-only guard missed a real serialization bug; the runtime probe reproduced and verified the fix. JSON5 field names are unchanged.
- **NeoForge real client GUI/nameplate validation (October 9):** DifficultyEx uses the JSON5 configuration and Fzzy Config's existing optional `/configure difficultyex` editor. No custom NeoForge Mods-button screen bridge is shipped; the editor is supplementary to configuration behavior. Before the property-annotation correction, all controls appeared **Not in Game** at the main menu and became editable in a world. Title-screen behavior must be rechecked after that correction. Tested in a newly generated disposable creative singleplayer world: a spawned cow displayed **Lv.1**, a colored ten-segment health bar and translated current/max HP; `/difficultyex set` updated it live to **Lv.20** and increased maximum HP. Toggling **Nameplates Enabled** to false via **Changes → Apply Changes** saved `false` to client JSON5 and removed the label immediately; applying true saved the setting and restored the label. Clicking only **Done** without applying discards pending edits (expected Fzzy behavior). This was a single integrated client, not a two-client network test. The test world and all temporary UI automation files were deleted and the original development JSON5 restored byte-for-byte. NeoForge dedicated-server startup and graceful shutdown passed during the configuration smoke test.
- **Both-loader config sync contract corrected (October 9):** Four bytecode tests now cover property and field annotations, server-authoritative fields, and matching loader schemas. A real NeoForge/Fzzy serialization probe applied server progression to two independent config objects while preserving different nameplate preferences. Authenticated two-client networking, reconnect, and GUI acceptance remain pending.
- **NeoForge live config smoke test:** an existing development JSON5 config loaded successfully with the new validated types; a temporary `entityStartingLevels` map entry forced a freshly spawned zombie to level **25**, with 60 max HP and 6 armor. Removed the zombie and force-load ticket, restored the original config byte-for-byte, and stopped the development server. The later singleplayer GUI check verified the nameplate enabled toggle; map editing still needs GUI acceptance.
- Safe one-time legacy owo-lib JSON5 import on both loaders, only when a modern config is absent. 7 conversion/file-safety unit tests pass. Malformed blacklist and level-map entries are skipped without discarding valid rules; fractional/overflowing integer settings and non-finite rates retain modern defaults. **NeoForge runtime migration tested:** synthetic legacy defaults (starting level 17, maximum 200, structure radius 25, disabled nameplates) were imported before Fzzy Config initialization; server reached `Done`. Original development config restored byte-for-byte and temporary test file deleted. Legacy visual offset/scale/colors and per-player difficulty enum are intentionally not migrated.
- Public PlayerEx 5.0.1, Data Attributes 3.0.0, Remnant 3.0.0 dependencies.
- Shared mob-level persistence, synchronization and attribute-scaling implementation.
- Both loaders now validate all eight level-map value handlers with a minimum of 1 while retaining the full positive Int range and text-box editing. Optional-editor descriptions explain registry IDs, entity regex matching, maximum priority, and loaded structure origins. IDEA compilation and the 53-test full build pass; all eight handlers passed real-library validation/correction checks on NeoForge. GUI editing and automatic file correction still need acceptance.
- Operator level changes now preserve health below 1 HP and leave zero-health mobs at zero instead of imposing a 1-HP floor. Three shared health-rescaling tests cover fractional health, dead/invalid inputs, and over-healed/extreme finite inputs. Compilation and both-loader test/build passed; the real server command dispatcher now passed fractional-health and zero-health cases on a disposable cow.
- Player-level averaging now falls back to decimal summation when finite formula results overflow the double sum. Three regressions cover cancellation in both orders, small remaining contributions, and truly huge averages saturating to integer limits. The ordinary calculation is unchanged. IDEA compilation and its full test/build run passed.
- **NeoForge real damage pipeline tested (October 8):** temporary local QA command spawned scaled zombies and cow targets in a disposable world and used `Zombie.doHurtTarget` and `Zombie.hurt` with a normal mob-attack `DamageSource`. Level-1 zombie attack attribute 3.3 dealt **3.3000002** actual damage; level-20 attribute 9.0 dealt **9.0**. Armor at level 1 was **2.16**, receiving **4.92/5** damage; armor at level 20 was **5.2**, receiving **4.50/5**. Both attacks and both armor hits passed, proving real Minecraft damage and armor mitigation reflect the scaled attributes. This was mob-versus-mob combat only, not a human-controlled player test. Temporary command was removed and RCON/forced chunks cleaned up.
- Moved attribute multiplier calculation to `DifficultyAttributeMath` with five unit tests (unchanged finite-rate behavior, zero/negative rates, capped huge modifiers, and rejecting NaN/infinities).
- **NeoForge PlayerEx spawn integration live-tested (October 8):** on the loopback-only disposable development server, a temporary QA command used NeoForge fake players with real `PlayerStateService.set` progression states (no actual accounts or online players were modified). **Eight scenarios passed** through real `Zombie` initialization: fallback 7 without players; level 23 near one player; levels 10 and 30 average to 20; distant level 100 excluded; `x*2` formula produces 40; exactly 10 blocks away included at level 19; 10.0001 blocks away excluded; player 11 blocks higher excluded. Removed temporary player references and test mobs, deleted the temporary QA command/helper, cleared the force-load ticket, stopped the server and restored RCON settings. Actual online-player multiplayer behavior is still untested.
- Player eligibility now explicitly excludes spectators to avoid staff observers changing enemy progression. Extracted pure 3D distance/inclusive-radius and transformed PlayerEx level-averaging logic into five tests plus a spectator-policy test; guards non-finite formula results and falls back to starting level when no eligible player result remains.
- **Verified live on NeoForge:** `/difficultyex inspect` and `/difficultyex set` both execute; an invulnerable test zombie scaled from level 1 (21.6 maximum health) to level 10 (36) and level 20 (52). Changing level at half health preserved the ratio (18/36 → 26/52).
- **Persistence regression fixed and retested:** the initial restart retained level 20 and maximum health 52 but incorrectly clamped saved health from 26 to 20. The fix captures raw NBT Health during load and restores it after modifiers, giving level 20, **26/52 health**, and 52 maximum health after the next save/restart. The test entity and forced chunk ticket were cleaned up.
- Shared XP reward calculation now guards non-finite configured rates and saturates oversized results. Fixed a real override gap: `Animal.getBaseExperienceReward` never reaches `Mob`, so the hook now scales the `LivingEntity.getExperienceReward` base XP argument before enchantment adjustments for all mobs. Five arithmetic tests pass.
- **NeoForge live XP-orb regression passed (October 8):** in the isolated development world, a temporary operator-only probe simulated real player-attributed deaths using NeoForge `FakePlayer` and the normal `hurt`/`dropExperience` paths. Level-1 zombie dropped **5 XP**, level-20 zombie **15 XP**, and a level-100 cow **11 XP** (random animal base roll 1, multiplied by 11). **9 XP orbs summed to 31 XP**, matching rewards. The temporary probe and RCON helper were deleted after testing; mobs, orbs and force-load tickets were cleaned up. A human-controlled player kill remains a separate acceptance test.
- **NeoForge entity metadata network codec verified (October 8):** a temporary operator-only QA command spawned a zombie in the isolated world, set its synced mob level to **12**, encoded and decoded the real `ClientboundSetEntityDataPacket.STREAM_CODEC`, and applied the decoded data to a separate zombie instance with `SynchedEntityData.assignValues`. The receiver reported **12**; a subsequent `packDirty` update to level **27** round-tripped and the receiver reported **27**. This validates serialization and tracked-field compatibility without an actual remote client. The QA class and local RCON helper were removed, the test zombie discarded, the force-load ticket removed, and RCON disabled. Authenticated client/server integration remains untested.
- **Nameplate language fix and NeoForge client retest (October 8):** verified in the actual Minecraft 1.21.1 `TranslatableContents` bytecode that `%s` is supported but `%d` raises a translation format exception and triggers literal-text fallback. Fixed health from `HP: %d/%d` to `HP: %s/%s`, removed incorrectly encoded legacy formatting from four nameplate translations, and applied yellow/gray styles through Minecraft `Component.withStyle`. Three tests load the packaged UTF-8 `en_us.json` resource and verify its placeholders and formatting. The NeoForge development client initialized the mod, Fzzy configs, resource manager and texture atlases without a client mixin error, then closed cleanly. This is a startup smoke test, not a visual verification of a rendered nameplate.
- **Nameplate stability and efficiency:** cached up to 256 mob/nameplate blacklist regex patterns, including malformed entries, with an explicit cache clear on config updates. Added pure health-label math so alive mobs never show an empty 10-segment bar, damaged mobs never appear fully healed, and non-finite values render safely. Eight new unit tests cover matcher behavior, invalid entries, health thresholds, and boundary handling.
- Client-side mob nameplate mixins compiled and packaged for both loaders: level, ten-segment textual health bar and separately togglable health numbers, hostile-only, distance, visibility and blacklist options. Nameplate override now honors Minecraft team visibility (`NEVER`, own-team/other-team restrictions), viewer-relative invisibility and the global render-names setting. No extra labels are forced when all three text/bar toggles are off. Four new policy tests pass; visual behavior still needs in-world verification.
- Structure-specific minimum/maximum levels and configurable horizontal radius (loaded chunks only; cap 128), with deterministic combined bounds. Extracted pure bounding-rectangle and chunk-range functions using Long intermediate coordinates to prevent edge overflow; five boundary tests cover inclusive edges, zero/capped radius, negative chunks and integer extremes. **Fixed an implicit load risk:** `StructureManager.startsForStructure` resolves structure-origin references with `getChunk` even when its queried reference chunk is loaded. Structure matching now reads `getChunkNow` for reference chunks and origins and never requests an absent origin chunk.
- **Verified live on NeoForge (October 8):** located a naturally generated `minecraft:village_taiga` at X=0, Z=608. A zombie inside its structure influence gained level 30 from `structureStartingLevels`; an outside control zombie remained level 1. After reloading with a conflicting level-20 `structureMaximumLevels` entry, a newly spawned village zombie was level 20 (maximum takes precedence).

Once `(0,38)` was explicitly force-loaded, a second zombie at the same position spawned at **level 30**. The original zombie retained level 1 as intended. Removed both test mobs and all three force-load tickets; removed the QA command/script and restored the ignored development config byte-for-byte.
- **Exact radius boundaries live-tested on the same generated village:** structure bounding box X=−87..53, Z=530..685, configured radius=16 and minimum level=30. X positions −103 and 69 were level 30; −104 and 70 level 1. Z positions 514 and 701 were level 30; 513 and 702 level 1. Corner (−103, 514) level 30; (−104, 514) level 1. Ten disposable zombies killed, all force-load tickets removed, original development config restored byte-for-byte, and server stopped. Temporary QA commands were deleted, not shipped.

## Fabric integration blocker

Reproduced again on October 9 in an isolated background Fabric server. The public release list still identifies 5.0.1 as the latest 1.21.1 release: the **public PlayerEx 5.0.1 Fabric JAR** crashes during `runFabric1211Server` at `playerex.mixins.json:ItemStackGameplayMixin`. The `playerex$preserveBrokenEntity` injector declares a `LivingEntity` parameter, but the Minecraft 1.21.1 target method requires `ServerPlayer`. This must be corrected in PlayerEx and released as a new compatible artifact before end-to-end DifficultyEx tests on Fabric.
