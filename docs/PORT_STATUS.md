# DifficultyEx 1.21.1 Port Status

Development snapshot — October 8, 2026. Not release-ready.

## Working foundation

- Builds on Gradle 9.8.0, Cloche 0.19.13, Java 21, and Kotlin.
- Fabric and NeoForge project layouts; Fzzy Config, no owo-lib/KSP.
- Fzzy fields now use validated wrappers so all configured progression, mob, world, structure, and nameplate fields are eligible for in-game edit controls (rather than raw values that never render editable controls). Nameplates use `@field:NonSync` client-only flags, confirmed in compiled NeoForge bytecode. JSON5 field names are unchanged.
- **NeoForge live config smoke test:** an existing development JSON5 config loaded successfully with the new validated types; a temporary `entityStartingLevels` map entry forced a freshly spawned zombie to level **25**, with 60 max HP and 6 armor. Removed the zombie and force-load ticket, restored the original config byte-for-byte, and stopped the development server. Client config GUI interaction remains to be verified visually.
- Safe one-time legacy owo-lib JSON5 import on both loaders, only when a modern config is absent. 4 conversion/file-safety unit tests pass. **NeoForge runtime migration tested:** synthetic legacy defaults (starting level 17, maximum 200, structure radius 25, disabled nameplates) were imported before Fzzy Config initialization; server reached `Done`. Original development config restored byte-for-byte and temporary test file deleted. Legacy visual offset/scale/colors and per-player difficulty enum are intentionally not migrated.
- Public PlayerEx 5.0.1, Data Attributes 3.0.0, Remnant 3.0.0 dependencies.
- Shared mob-level persistence, synchronization and attribute-scaling implementation.
- **NeoForge PlayerEx spawn integration live-tested (October 8):** on the loopback-only disposable development server, a temporary QA command used NeoForge fake players with real `PlayerStateService.set` progression states (no actual accounts or online players were modified). **Eight scenarios passed** through real `Zombie` initialization: fallback 7 without players; level 23 near one player; levels 10 and 30 average to 20; distant level 100 excluded; `x*2` formula produces 40; exactly 10 blocks away included at level 19; 10.0001 blocks away excluded; player 11 blocks higher excluded. Removed temporary player references and test mobs, deleted the temporary QA command/helper, cleared the force-load ticket, stopped the server and restored RCON settings. Actual online-player multiplayer behavior is still untested.
- Player eligibility now explicitly excludes spectators to avoid staff observers changing enemy progression. Extracted pure 3D distance/inclusive-radius and transformed PlayerEx level-averaging logic into five tests plus a spectator-policy test; guards non-finite formula results and falls back to starting level when no eligible player result remains.
- **Verified live on NeoForge:** `/difficultyex inspect` and `/difficultyex set` both execute; an invulnerable test zombie scaled from level 1 (21.6 maximum health) to level 10 (36) and level 20 (52). Changing level at half health preserved the ratio (18/36 → 26/52).
- **Persistence regression fixed and retested:** the initial restart retained level 20 and maximum health 52 but incorrectly clamped saved health from 26 to 20. The fix captures raw NBT Health during load and restores it after modifiers, giving level 20, **26/52 health**, and 52 maximum health after the next save/restart. The test entity and forced chunk ticket were cleaned up.
- Shared XP reward calculation now guards non-finite configured rates and saturates oversized results. Fixed a real override gap: `Animal.getBaseExperienceReward` never reaches `Mob`, so the hook now scales the `LivingEntity.getExperienceReward` base XP argument before enchantment adjustments for all mobs. Five arithmetic tests pass.
- **NeoForge live XP-orb regression passed (October 8):** in the isolated development world, a temporary operator-only probe simulated real player-attributed deaths using NeoForge `FakePlayer` and the normal `hurt`/`dropExperience` paths. Level-1 zombie dropped **5 XP**, level-20 zombie **15 XP**, and a level-100 cow **11 XP** (random animal base roll 1, multiplied by 11). **9 XP orbs summed to 31 XP**, matching rewards. The temporary probe and RCON helper were deleted after testing; mobs, orbs and force-load tickets were cleaned up. A human-controlled player kill remains a separate acceptance test.
- Client-side mob nameplate mixins compiled and packaged for both loaders: level, ten-segment textual health bar and separately togglable health numbers, hostile-only, distance, visibility and blacklist options. Nameplate override now honors Minecraft team visibility (`NEVER`, own-team/other-team restrictions), viewer-relative invisibility and the global render-names setting. No extra labels are forced when all three text/bar toggles are off. Four new policy tests pass; visual behavior still needs in-world verification.
- Structure-specific minimum/maximum levels and configurable horizontal radius (loaded chunks only; cap 128), with deterministic combined bounds. Extracted pure bounding-rectangle and chunk-range functions using Long intermediate coordinates to prevent edge overflow; five boundary tests cover inclusive edges, zero/capped radius, negative chunks and integer extremes. **Fixed an implicit load risk:** `StructureManager.startsForStructure` resolves structure-origin references with `getChunk` even when its queried reference chunk is loaded. Structure matching now reads `getChunkNow` for reference chunks and origins and never requests an absent origin chunk.
- **Verified live on NeoForge (October 8):** located a naturally generated `minecraft:village_taiga` at X=0, Z=608. A zombie inside its structure influence gained level 30 from `structureStartingLevels`; an outside control zombie remained level 1. After reloading with a conflicting level-20 `structureMaximumLevels` entry, a newly spawned village zombie was level 20 (maximum takes precedence).
- **NeoForge unloaded-origin regression live-tested (October 8):** In the generated taiga village, with radius 16 and level-30 structure minimum, only chunks `(-7,37)` and `(-6,37)` were force-loaded. Chunk `(-6,37)` contained a `minecraft:village_taiga` reference, while the origin chunk `(0,38)` was confirmed absent by a non-loading QA probe. A zombie at X=-103,Z=600 spawned at **level 1**; the origin remained absent after the mob-level lookup. Once `(0,38)` was explicitly force-loaded, a second zombie at the same position spawned at **level 30**. The original zombie retained level 1 as intended. Removed both test mobs and all three force-load tickets; removed the QA command/script and restored the ignored development config byte-for-byte.
- **Exact radius boundaries live-tested on the same generated village:** structure bounding box X=−87..53, Z=530..685, configured radius=16 and minimum level=30. X positions −103 and 69 were level 30; −104 and 70 level 1. Z positions 514 and 701 were level 30; 513 and 702 level 1. Corner (−103, 514) level 30; (−104, 514) level 1. Ten disposable zombies killed, all force-load tickets removed, original development config restored byte-for-byte, and server stopped. Temporary QA commands were deleted, not shipped.
- `gradlew.bat clean test build` passed for both loaders; JUnit XML reports **28 tests** (four level bounds, five structure geometry, six PlayerEx math/eligibility, five XP math, four legacy config migration and four nameplate visibility), 0 failures, 0 errors.
- NeoForge client smoke test after the nameplate visibility update loaded DifficultyEx and other mod resources/config, initialized render resources/texture atlases, and reported no startup mixin failures. Test client was closed. Actual in-world nametag rendering and layout remain untested.
- New structure fields were missing in the existing development config on first load; Fzzy Config reported missing keys and wrote their defaults into `run/config/difficultyex/config.json5`.
- MixinMCP Gradle decompile plugin 1.5.0 configured.
- Developer metadata and all package paths use `pokesmells` (`dev.pokesmells.difficultyex`); former source namespace no longer appears in Java/Kotlin code.
- Repository root now uses BML v1.0 from the studio license, retaining the inherited MIT notice in `docs/ORIGINAL_MIT_LICENSE.txt`. Both license texts are included in each loader JAR.
- `gradlew.bat build` succeeds for both loaders after adding shared operator-only `/difficultyex inspect` and `/difficultyex set` commands, with loader-specific registrations. The setter retains the target mob's health percentage.
- Git development work is restricted to the `1.21.1` branch; the push/publication pipeline remains manual and is now explicitly gated to that branch.

## Fabric integration blocker

Verified again after the `dev.pokesmells` package migration: the **public PlayerEx 5.0.1 Fabric JAR** crashes during `runFabric1211Server` at `playerex.mixins.json:ItemStackGameplayMixin`. The `playerex$preserveBrokenEntity` injector declares a `LivingEntity` parameter, but the Minecraft 1.21.1 target method requires `ServerPlayer`. This must be corrected in PlayerEx and released as a new compatible artifact before end-to-end DifficultyEx tests on Fabric.
